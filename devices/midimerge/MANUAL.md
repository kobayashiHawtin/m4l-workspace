# midimerge — 取扱説明書

midimerge は、**2つのトラックのMIDIフレーズ（A と B）を MORPH ひとつで混ぜる** Max for Live MIDIエフェクトです。
同じトラック・同じ音源のまま、2つのMIDIクリップをクロスフェードしたり、フレーズ単位で切り替えたりできます。

```
[Track A]  MIDI ─▶ [ midimerge ] ─▶ [ 音源 ] ─▶ 出力
                        ▲
                  バス通信 (BUS 1〜8)
                        │
[Track B]  MIDI ─▶ [ midisend ] ─▶ (Track B の音源・任意)
```

---

## はじめに

このデバイスは「**確率だけでは面白くない**」という素朴な出発点から生まれました。

各ノートをコイン投げで A か B に振る Prob は、確かにランダムですが、音楽的には散らばるだけで「流れ」にはなりません。面白いのは**水路**を作ることです。どこからどこへ流れるかを決め、条件と記憶を持たせます。マルコフ連鎖はまさにそれで、名前のいかつさに反して「次にどこへ行くかを、前の状態で決める」だけの単純な仕組みです。

もうひとつの出発点は「**何で2つのパターンをモーフするか**」です。確率以外にも、ベロシティ、時間、音程……と媒介を変えれば、まったく違う音楽になります。midimerge の MODE はその試みです。Density はベロシティのクロスフェード、Prob は確率、Swap はリズムと音程の切り分け、そして Markov は**記憶**です。

Markov モードは、Max for Live の生成デバイス **AE Machine**（https://www.peamarte.it/ae/）に着想を得ています。同作の Default / Bias と「システム安全性」（袋小路に陥らない抜け道、行き先の保証）という考え方を、midimerge では **Bias** という名前で受け継ぎました。

## 1. セットアップ

### なぜ `midisend` を使うのですか
Live 標準のルーティング（Track B の `MIDI To` を Track A に向ける方法）では、B のノートは A トラックの**先頭**（midimerge より前）に入ってしまい、midimerge は A と B を区別できません。そこで `midisend` とバス（BUS 1〜8）を使い、**B のノートを midimerge の専用 B 入力へ直接届けます**。BUS 番号が同じデバイス同士がペアになります。

### ステップ 1: デバイスを挿します
- **Track A**（メイン音源トラック）: 音源の**前**に `midimerge` を挿します。
- **Track B**: `midisend` を挿します。その後に音源を置けば、B 自身の音も聴けます。

### ステップ 2: 通信を設定します
1. `midimerge` と `midisend` の **BUS 番号を同じ数値（1〜8）** にします。これで2つのトラックがリンクします。
2. **B の音を二重に鳴らさないようにします**: モーフ後の音だけを聴きたい場合は **Track B をミュート**してください（または B の音源・出力を鳴らさないようにしてください）。`midisend` は B の音源にもノートを通す（パススルーする）ためです。
3. **Track B の `MIDI To` は `No Output` のまま**にしてください。B を A へ直接ルーティングするとモーフを迂回して **B が常に鳴ります**。
   ※ 音源を挿したトラックは出力が音声になり `MIDI To` が出ませんので、この問題は起きません。
4. デバイスを更新したら、Live では **削除 → 再追加**してください（Live はデバイスUIをキャッシュします）。

## 2. パラメータ仕様

| パラメータ | 範囲 / 初期値 | 有効モード | 機能 |
|---|---|---|---|
| **BUS** | 1–8 / 1 | 全 | Track B（`midisend`）と送受信するバス番号です。 |
| **MORPH** | 0–100 / 0 | 全 | **A と B のブレンド具合**です。0 = A のみ、100 = B のみです。意味は MODE で変わります。 |
| **MODE** | Density, Prob, Swap, Markov / Density | — | ブレンド方式です（§3）。 |
| **TIMING** | A, B / A | Swap のみ | どちらのトラックのリズム（発音タイミング）を優先するかを選びます。他モードではグレーアウトします。 |
| **LOW** | 0–127 / 0 | Density・Prob・Swap | モーフを適用する最低ノート番号です。LOW〜HIGH の範囲外の音は常に A になります（B は無音です）。 |
| **HIGH** | 0–127 / 127 | Density・Prob・Swap | モーフを適用する最高ノート番号です。LOW〜HIGH の範囲外の音は常に A になります（B は無音です）。 |
| **SLEW** | 0–1000 ms / 40 | 全 | MORPH の追従スムージングです。上げるとオートメーション時の変化が滑らかになります。 |
| **STICK** | 0–100 / 50 | Markov のみ | 同じ側が選ばれ続ける度合いです。高いほど A または B がまとまった塊（ラン）で続きます。 |
| **BIAS** | 0–100 / 0 | Markov のみ | A へ引き戻す確率です。上げると B に居座り続けるのを防ぎ、基本の A へ戻りやすくなります。 |

## 3. MODE（ブレンド方式の詳細）

### 3.1 Density — ベロシティ・クロスフェード
ノートの発音タイミングはそのままに、**ベロシティを連続的にクロスフェード**します。
- **動作**: ノートオンを間引かず、A のベロシティを下げながら B を上げます（A = `1−MORPH`、B = `MORPH` の倍率です）。ノートは再発音されません。
- **前提**: ベロシティに応じて音量・フィルター・エンベロープが変わる音源で効果を発揮します（シンセや生楽器系などです）。ベロシティを無視する音源では差が聴こえませんので、ノート自体を差し替える **Prob** を使ってください。
- **活用例**: 同じフレーズの別テイクを継ぎ目なく重ねたり、静かに片方へ寄せたりできます。

### 3.2 Prob — 確率抽選
ノートが発音されるたびに、**MORPH の確率で B を採用するかどうかを抽選**します。
- **動作**: コイントスのように音符単位で選ばれます。A と B は**独立に間引かれる**ため、発音タイミングが重なれば同時に鳴ることもあります（両方消えることもあります）。
- **活用例**: ハイハットやパーカッションをランダムに差し替えたり、偶発的なバリエーションを作ったりできます。

### 3.3 Swap — グルーヴ＆ピッチ・スワップ
一方の**リズム（発音タイミング）を維持したまま**、**音程だけ**をもう一方へ寄せます。
- **動作**: TIMING で選んだ側のノートオンを使い、その音程を、**そのノートの音程**と**もう一方の直近の音程**の中間（整数に丸めます）へ MORPH で寄せます。
  - **TIMING = A**: A のリズムのまま、音程を A → B へ移行します。
  - **TIMING = B**: B のリズムのまま、音程を B → A へ移行します。
- **活用例**: 同じグルーヴのままコード進行だけを滑らかに変えたり、キーを移行したりできます。

### 3.4 Markov — フレーズ単位の切り替え
1音ごとのバラバラな切り替えではなく、**フレーズのかたまりとして A と B を行き来**します。
- **動作**: 共有の「**side**」（A か B です）を1つ持ち、**ノートオンごとに前進**させます。各ノートは、自分のストリームが side と一致するときだけ鳴ります。出力は「ラン（かたまり）」になります（例: `A A A B B A A …`）。
- side の決まり方は、各ノートオンで次の順に判定します。
  1. **BIAS**% の確率で **A に固定**します。
  2. そうでなければ、**STICK**% の確率で **今の side を維持**します。
  3. それ以外は、**MORPH の確率で再抽選**します（P(B) = MORPH）。
- MORPH=0 なら常に A、100 なら常に B になります（STICK=0 のときです）。STICK を上げると同じ側が長く続きます。

| つまみ | 役割 |
|---|---|
| MORPH | A/B の**目標比率**です。 |
| STICK | 同じ側が**選ばれ続ける度合い**（フレーズの長さ）です。 |
| BIAS | B に居座り続けないための**アンカー**（A へ戻す）です。 |

- **LOW/HIGH は Markov では使われません**（機能自体が無効になります）。
- **活用例**: A を主軸にしつつ、ときどき B へ数小節だけ寄り道して自然に A へ戻る、といった自動オーケストレーションができます。

## 4. クイック・レシピ

- **ストリングスやパッドをじんわり切り替えたい**: `MODE: Density` / `SLEW: 500ms` にして、MORPH を Live の LFO でゆっくり動かします。
- **スネアにときどきゴーストノートを混ぜたい**: `MODE: Prob` / `MORPH: 25` / `LOW: 38 (D1)` / `HIGH: 40 (E1)` にします。スネアの音域だけに絞り、4回に1回ほど B を差し込みます。
- **ベースはそのまま、上モノだけ別パターンにしたい**: `LOW: 60 (C3)` / `HIGH: 127` にします。低音域をモーフから除外できます。
- **フレーズのキャッチボールをしたい**: `MODE: Markov` / `MORPH: 50` / `STICK: 80` / `BIAS: 15` にします。数拍〜数小節単位でまとまって入れ替わり、放っておくと自然に A へ帰還します。

## 5. トラブルシューティング / FAQ

- **Q. B の音がダブります／モーフしていない生の B が鳴ります**
  - **原因**: Track B 自身の音源またはトラック出力が鳴っています。
  - **対策**: Track B をミュートしてください（または B の音源・出力を鳴らさないようにしてください）。`midisend` は B の音源へパススルーするためです。
- **Q. Track B の `MIDI To` を A にしたら B が常に鳴るようになりました**
  - **原因**: B のノートが A トラックの先頭（midimerge より前）へ入り、モーフを迂回しています。
  - **対策**: `MIDI To` は `No Output` のままにしてください。バス（BUS）で繋いでください。
- **Q. LOW / HIGH が Markov モードで効きません**
  - **仕様**: Markov はストリーム全体の side を切り替えるモードで、LOW/HIGH による音域制限は適用されません。音域を絞りたい場合は、トラック側で事前にフィルタリングしてください。
- **Q. アップデートしたのに UI や挙動が変わりません**
  - **対策**: Live が古いデバイス状態をキャッシュしています。トラックから `midimerge` を削除し、ブラウザから再インサートしてください。
